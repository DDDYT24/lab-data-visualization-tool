# 公开发布检查清单

本文面向仓库维护者，用于把本地版本发布到 GitHub。以下文件都应随源代码上传；本清单
不要求上传用户数据或本机运行目录。

## 应上传的内容

| 文件 | 给谁看 | 作用 |
| --- | --- | --- |
| `README.md`、`README.zh-CN.md` | 所有用户 | 安装、启动、功能和默认数据边界 |
| `V2.0/docs/PRIVACY_DATA_BOUNDARY.md` | 用户、实验室管理员 | 说明数据是否离开本机以及例外配置 |
| `V2.0/docs/OFFLINE_INSTALL.md` | 用户、部署管理员 | 说明依赖、地址和离线运行方式 |
| `V2.0/docs/BACKUP_RESTORE.md` | 用户、实验室管理员 | 说明本地数据备份与恢复 |
| `SECURITY.md` | 安全报告者、维护者 | 报告问题和本地安全边界 |
| `CONTRIBUTING.md` | 贡献者 | 开发环境、测试和公开文档约定 |
| `CHANGELOG.md` | 所有用户 | 版本变化和已知限制 |

## 不应上传的内容

- `V2.0/api/.labviz/`、`.env`、密钥、验证码、数据库备份和对象目录；
- 真实实验文件、真实导出图、含个人信息的截图和日志；
- `outputs/` 下的本机生成测试包（除非另行整理为公开、合成且可复现的 fixture）；
- 个人绝对路径、内部分支名、内部会话记录和未公开的服务地址；
- 任何只对本地编辑过程有意义、对用户没有帮助的工具或自动化说明。

## 发布前顺序

1. 确认 README 的版本、启动命令和默认本地路径与代码一致。
2. 运行隐私边界检查，确认默认 API/网站只绑定回环地址，前端没有遥测或外部数据接口。
3. 运行 API、前端、浏览器和 fixture 回归；把未配置的云端或真实邮件测试明确标为未验证。
4. 检查 `git status` 和 `git diff --cached`，确认没有数据、密钥、构建缓存和本机路径。
5. 更新 `CHANGELOG.md` 和 V2.1 发布说明，再创建版本标签和 GitHub Release。
