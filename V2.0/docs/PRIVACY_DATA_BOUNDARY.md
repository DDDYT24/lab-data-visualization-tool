# LabViz 本地隐私边界

本文面向使用 LabViz 处理实验数据的用户和实验室管理员。V2.1 的默认发布方式是
**单台电脑本地部署**，不提供官方在线服务，也不会自动把数据上传到项目维护者的数据库。

## 默认数据路径

启动脚本默认只启动本机回环地址：

```text
浏览器
  │ http://127.0.0.1:3000
  ▼
Next.js 网站
  │ http://127.0.0.1:8000
  ▼
FastAPI 处理服务
  ├─ SQLite：V2.0/api/.labviz/labviz-v2.db
  └─ 本地对象目录：V2.0/api/.labviz/objects/
```

上传文件由本机 FastAPI 读取和处理。上传期间，Web 框架可能使用内存或操作系统临时目录做
缓冲；这不等同于项目资产，生命周期由运行时控制。原始上传文件不会作为原文件长期写入项目
资产；为支持历史记录、清洗、重新绘图和导出，解析后的数据快照、质量报告、图表配置和导出
结果会留在本机 SQLite 或本地对象目录中。临时项目和导出结果默认在两小时没有继续操作后过期；
保存的项目会一直留在本机，直到用户删除项目或删除本地运行数据。

启动脚本和仓库 CI 会设置 `NEXT_TELEMETRY_DISABLED=1`，默认运行不包含遥测、统计上报或
第三方数据接口。首次安装时，`pip` 和 `npm` 需要从配置的
软件包源下载依赖；这一步只下载软件包，不上传用户实验数据。依赖安装完成后，应用的数据
请求默认只在本机回环地址之间传输。

## 运行时依赖是什么

| 组件 | 用户是否需要单独安装 | 实际来源 |
| --- | --- | --- |
| FastAPI、Uvicorn 等 | 不需要手动逐个安装 | 启动脚本在 `V2.0/api/.venv` 中通过 `pip install -r requirements.txt` 安装 |
| SQLite | 不需要安装数据库服务器 | Python 自带的 `sqlite3` 标准库；应用自动创建 `.labviz/labviz-v2.db` |
| Next.js、React 等 | 不需要手动逐个安装 | 启动脚本在 `V2.0/web` 中通过 `npm ci` 安装 |
| PostgreSQL、MinIO/S3、AWS、Docker | 本地使用不需要 | 仅供维护者做多进程、容器或远程存储测试 |

因此，普通用户只需要安装支持的 Python、Node.js 和现代浏览器，然后运行仓库中的启动脚本。

## 什么情况下数据会离开本机

只有在用户主动改变部署配置或网络边界时，数据才可能离开本机，例如：

1. 把 `LABVIZ_PERSISTENCE_BACKEND` 改为 `postgresql`，并填写远程 PostgreSQL 地址；
2. 把 `LABVIZ_OBJECT_STORAGE_BACKEND` 改为 `s3`，并配置远程对象存储；
3. 设置 `NEXT_PUBLIC_LABVIZ_API_URL` 指向另一台机器的 API；
4. 配置外部 SMTP/SES，或把网站/API 绑定到 `127.0.0.1` 之外并开放端口；
5. 用户主动把导出的图表、清洗数据或只读分享链接发送给他人。

本地分享链接只是一种本地访问控制机制。若服务端口被局域网或公网访问，拿到链接的人可能
读取分享内容，所以机密数据不应使用公开端口或分享链接。

## 机密数据建议

- 保持启动脚本的默认绑定地址 `127.0.0.1`，不要把 3000 或 8000 映射到公网。
- 不设置上述远程数据库、对象存储和远程 API 变量。
- 将 `V2.0/api/.labviz/` 视为实验数据目录，避免放入 OneDrive、网盘或自动同步目录。
- 使用操作系统磁盘加密，并把数据库和对象目录纳入实验室自己的备份策略。
- 不要把 `.labviz/`、`.env`、原始实验文件或导出结果手动加入 Git 提交。
- 如果需要真正的“处理后不落盘”模式，目前版本尚未提供；应把它作为独立需求实现和验证，
  不能把默认本地持久化误认为内存模式。

## 删除本地数据

停止网站和 API 后，删除 `V2.0/api/.labviz/` 会移除本地项目、会话、历史和处理结果。原始
实验文件若保存在其他位置，需要按实验室的数据保留制度单独处理。删除前请先阅读
[`BACKUP_RESTORE.md`](BACKUP_RESTORE.md)。
